# Classify before rewriting

Preserve behavior; reduce the text needed to reach it. Inventory the current
rules before drafting replacement prose.

## Dispositions

| Signal | Disposition | Evidence needed |
|---|---|---|
| Live instruction used on every path | Keep in the entry workflow | A task that needs it |
| Useful rule buried in a long explanation | Condense | Trigger, action, reason and exceptions survive |
| Detailed recipe used only on one branch | Move to a topic reference | An entry pointer states when to load it |
| Another skill owns the same behavior | Delegate by pointer | Read its actual content; verify availability for intended profiles |
| Incident narrative | Extract the general rule, then remove the story | The rule still applies; identifiers and decisions are preserved |
| Stale command or obsolete workflow | Remove or replace | Current tool/source evidence; absence from a search alone is not proof |
| Easily discovered list or fact | Replace with a lookup hint | The lookup exists and the fact carries no hidden convention |
| Repeated rule within the skill | Consolidate | One authoritative home and no lost exception |
| Contradictory live rules | Ask before rewriting | Identify which behavior differs and who can decide |

## Protect intent

A user preference is not disposable history. “The owner rejected automatic
retries” carries policy even if learned in an incident. Retain the decision as a
current rule; remove the anecdote. Preserve the reason when it explains a choice
that an agent might otherwise reverse.

Do not delete a command merely because `--help` lists it. Its placement in the
workflow, identity selector, required working directory or approval gate may be
the information that matters. Preserve exact identifiers; verify replacements.

A repeated permission boundary can be useful at the action site. Consolidate its
definition, but keep a short local reminder if removing it makes execution unsafe.

## Section ledger

Use one row per coherent unit, not just per heading:

| Source section | Disposition | Destination | Evidence |
|---|---|---|---|
| Runtime recipe | Delegate | runtime skill, Launch section | Covers the same identity and directory constraints |
| Recovery story | Condense | reference, Recovery | Stable action remains; event-specific names removed |
| Approval sentence | Keep | entry, Authority | Explicit owner decision |

Include scripts, templates and assets in the ledger. Moving their callers can
break relative paths even when no script code changes. Recheck those paths after
installation. An unused-looking asset needs a caller search before deletion.

## Rewrite standard

State the trigger, action, completion condition and meaningful exception. Use an
imperative sentence for an action. Keep a brief reason for a non-obvious constraint.
Use generic examples, present-state rules and consistent terms. Avoid incident
chronology, repeated warnings and speculative fallback branches.

A good condensation:

> Before replacing a document, compare it with the version last read. Merge any
> intervening edits so another writer's changes are preserved.

A bad condensation:

> Be careful when writing.

The second is shorter but deletes the executable rule.
