# ui-design

A short, ordered process for any interface design task.

## When an agent uses it

You ask for a UI or component design and want the agent to follow a clear process.

## The steps

1. Reason about the product first: what it is, who uses it and when, and which affordances and signifiers the screen needs. Concrete, calm copy; no reassuring filler.
2. Gather references: a saved UI library first (for example a `uirefs` MCP server through `ui-reference-search`), then the web beyond the obvious: competitors, products from other niches that share a problem, showcase sites (Awwwards, 60fps.design) and designers' posts on X. Name each reference and what was taken from it.
3. Choose the brand system on purpose: a typeface chosen for the identity, with a reason; white backgrounds or a real colour, never beige or paper tones; one accent with one meaning.
4. Stay within platform conventions (least astonishment).
5. Build reusable components, and reuse an existing one before creating a new one.
6. Find the icon opportunities with `find-icon-opportunities`.
7. Keep one design language: the same colours, fonts and iconography.
8. Keep settings compact and contextual: put a control next to the item it affects, in the existing row, not in a duplicate row.

## Limits

No scripts or references. For mobile platform rules it points to `mobile-product-design`; for icons to `find-icon-opportunities`.
